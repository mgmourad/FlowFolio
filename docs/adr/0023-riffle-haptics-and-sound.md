# ADR-0023: Map the riffle scrubber's feedback to haptic constants by API level, and generate its paper sounds

- **Status:** Accepted (product owner, 2026-10-20: "the generated ones are fine")
- **Date:** 2026-10-20
- **Deciders:** product owner, lead engineer
- **Phase:** 2 (milestone M2b)

## Context

The riffle scrubber (ADR-0022) gives feedback while the reader drags its ribbon: ticks as pages pass, something
stronger at a chapter start, a double tick at a bookmark, and a tick at each fine-scrub speed threshold. It also plays
short paper sounds. The app's minimum SDK is 29 (ADR-0006); some haptic constants are newer. The spec asks for the
mapping to be recorded.

## Options considered

1. **`View.performHapticFeedback` with `HapticFeedbackConstants`.** Follows the user's system haptics settings and the
   device's tuned effects. Needs a fallback below the API level of each constant.
2. **`Vibrator` with our own waveforms.** Full control, but ignores the system's touch-feedback setting and feels
   different from the rest of the system.
3. **Recorded paper samples** versus **samples generated by our own script.** Recorded samples raise licence questions
   for every file; generated ones are ours (MIT) and match the mock, which synthesises its sounds.

## Decision

Option 1, with this mapping (the constant, then the fallback below its API level):

| Event | API 34+ | API 30–33 | API 29 |
|---|---|---|---|
| Pages passing (every 4 units) | `SEGMENT_FREQUENT_TICK` | `CLOCK_TICK` | `CLOCK_TICK` |
| Fine-scrub threshold crossed | `SEGMENT_TICK` | `CLOCK_TICK` | `CLOCK_TICK` |
| Chapter start crossed | `CONFIRM` | `CONFIRM` | `LONG_PRESS` |
| Bookmark crossed | `SEGMENT_TICK` twice, 40 ms apart | `CLOCK_TICK` twice | `CLOCK_TICK` twice |

`SEGMENT_TICK` and `SEGMENT_FREQUENT_TICK` were added in API 34, `CONFIRM` in API 30, `CLOCK_TICK` in API 21.
Haptics fire only for the reader's own drags: never during a flag's travel, a landing or a demo. A "Haptics" setting
turns them off.

Sounds are generated (option 3, generated):
- A standard-library Python script (`tools/sounds/make_paper_sounds.py`) writes a few short WAV files: paper flicks
  (filtered noise bursts), a lower thump for chapters, and a whoosh for landing sheets. They are committed as our own
  MIT assets, a few tens of kilobytes in all.
- They play through `SoundPool`, at most one every 18 ms, each at a random rate between 0.85 and 1.25 for variety.
- Nothing plays in silent or vibrate ringer modes. A "Paper sound" setting turns them off.

## Consequences

- Positive:
  - Haptics feel native and follow the user's system settings.
  - No third-party audio files and no new dependency.
- Negative / accepted risks:
  - Below API 34 the ticks are coarser (`CLOCK_TICK`).
  - Synthesised paper is less natural than a recording. If it doesn't sound right on the Fold, only the samples need
    replacing.
- Follow-ups:
  - **M2b R3 (lead engineer):** check the feel and loudness on the Fold, and tune the script's parameters.
